## drawdown: the app

A pour-over brew log for iPhone, used from Safari / home screen.

Features: one guided Brew page (checklist: 01 Beans · 02 Gear · 03 Recipe · 04 Brew · 05 Taste; done steps fold to a summary with "Change"); setups (brewer, hand or electric grinder, kettle, filter); beans (scan a bag photo or add by hand); brew log (dose, water, auto ratio, grind, temp, bloom, time, 1–5 stars, taste tags, notes); ring timer with pour plan; "Brew again"; Journal with All / Top rated / Calendar (brew days painted in each bean's photo palette) and best recipe per bean; next-brew advice (AI, or rule-based fallback); grinder-aware grind sliders.

### Code

- One file: `coffee/index.html` — vanilla JS, no build step, no dependencies. Plus `manifest.webmanifest` and `assets/` (icons, mark SVGs).
- **Storage adapters:** `cloudStore` (Claude artifact `db`, per user at `data/users/<id>`) when `window.claude` exists; otherwise `localStorage` key `brewlog-v1`. On GitHub Pages there is no `window.claude`, so data is **per device/browser only** and AI is off. Photo reading there uses **on-device OCR** (Tesseract.js 5.1.1 from jsDelivr, loaded on first scan) + `parseLabel()` rules (origin/region/process/varietal/altitude/date/notes lists; biggest text line = name) + `starterRecipe()` from the grinder zone. Bean "Suggest a recipe" and next-brew tips use the rule-based versions.
- **Account** (v1.17, Bodega pattern, backend in `drawdown/backend/`): `SUPA = {url, key}` (empty = off, app is device-only as before; tests inject `window.DRAWDOWN_SUPA`). No-library client `supa`: Google sign-in with PKCE (`signIn` → `/auth/v1/authorize`, `finishSignIn` swaps `?code` at `/auth/v1/token?grant_type=pkce`; never shows the URL's error text), refresh, `call()`. `supaStore()` checks `am_i_allowed`, loads `public.docs`, uploads guest docs the account lacks on first sign-in, reloads on visibilitychange. `supaAI()` = same shape as Claude's `sample` (callable + `.json`, `.web = true`) via the `ask` Edge Function (Claude key + daily quota); on failure the scan falls back to on-device reading. **v1.19:** `ask` v3 logs each model's Anthropic status/error (`console.error`, never the key) and returns `{error:'upstream', reason}` (credit · auth · rate · busy · network · model); `supa.call` passes `reason` on; `AI_WHY` turns it into a sentence. Next-brew advice never dead-ends: any AI failure → `ruleAdvice` with `advice.fallback` shown under the tip. Read the reason with Supabase `query_logs` on `function_logs`. Settings: Sign in with Google / Signed in · Sign out. **v1.24:** guest docs are handed to the account once per device (`drawdown-moved` = ids already handed over); before, every launch re-uploaded them, so deleted beans came back. No record + account has data + not a fresh sign-in (`supa.fresh`) → nothing uploaded.
- Docs in one collection, `kind`: `setup` | `bean` | `brew` | `prefs`. `prefs.plan` is the recipe queued on the Brew screen; cleared after logging.

- **Roast from tasting notes** (v1.12): `NOTE_ROAST` maps ~400 flavour-wheel words/phrases to a roast spot 0 (light) … 4 (dark); `noteWords` (longest phrase first), `roastScore` = average, `roastFromNotes` buckets <0.8 light · <1.6 light-medium · <2.4 medium · <3.2 medium-dark · dark. `parseLabel` fills `roastLevel` with the guess and sets `roastFrom:'notes'` when the bag prints no roast; `roastWhy` names the words. Locked in tests.
- **Hero timer** (picked from prototypes): huge Geist Mono time, serif instruction, greyscale bar (milk fill on `#2a2a2a`) with gram marks, "Next" line. On each phase change the instruction, hint and next line blur-rise in (`.swap`, 520 ms spring, staggered 0/60/110 ms). Controls: Start → Stop + Skip → Taste (stars, tags, notes, Log brew). The clock is a **rolling counter** (`rollTo`): each digit is a doubled wheel strip (0–9, tens-of-seconds 0–5) that rolls forward like an odometer, higher columns 45 ms later (the carry), edge-faded with a mask.

Hidden `<input type=range>` stays the source of truth. (v1.16: no V60 zone line on the grind slider — removed at Jeroen's request.) **v1.15 look:** one rhythm (52 px rows, 8 px gap, `.dkrow`, no ratio/hint lines in between — ratio sits in the water value, units in small sans). Track radius 12, the pull floats 3 px inside with radius 9, a soft top-lit gradient and shadow (the one exception to the square brand). Hashmarks hide under the label/value.
- **Sounds** (v1.11, recorded clicks v1.15): slider detents and taps are **Jeroen's own Ode Gen 2 recording** (`ODE_PCM`: 4 tight ~10 ms strikes + 2 tab clicks with a 160 Hz body, base64 PCM, from `Tik tok.m4a`, denoised, "B · tight" variant). Rest is synth: `SFX`, modal synthesis pre-rendered to AudioBuffers at unlock (no files; own design, bencho.dev couldn't be read): sub-ms noise strike + damped resonances + short low body sine, through highshelf -4 dB and a soft compressor. ±3 % pitch jitter per play. `tick(f)` slider detent = Fellow Ode Gen 2 dial click (`ode` spec, v1.14: faint pre-click as the detent lifts + dry ~2 kHz plastic tock + 420 Hz housing knock; pitch follows value, faster drags softer/lighter, ≥16 ms apart) · `end` heavier thunk at min/max · `snap` one firm Ode click · `tap` buttons · `second` watch tick/tock · `chime` bell on each new pour (880 Hz + inharmonic partials, beating pair) · `start`/`stop`. Toggle in Settings (`localStorage['drawdown-sound']`). **iOS unlock (v1.13):** audio only starts inside touchend/click/keydown/pointerup (not pointerdown), so `unlock()` listens on those (capture), resumes + plays a 1-sample silent buffer, and retries until running; resumes on visibilitychange. `navigator.audioSession.type = 'playback'` so it plays with the mute switch on (Settings "Play on silent", `drawdown-sound-silent`; off → 'ambient').
- **Bean palettes + calendar** (v1.10): `paletteFromImage(src)` → 3–5 hex colours from the bag photo (centre 80% crop, 64 px, 4-bit buckets scored by count × (1 + 2·saturation), greedy pick with min RGB distance 56). Stored on the bean as `palette` + `paletteOf` (photo length, so a new photo recomputes). `ensurePalette(id)` on bean save; `backfillPalettes()` once after load. No photo → `paletteFromNotes()` muted tones from flavour words, else greys. Journal has All · Top rated · Calendar (`calendarBody`, `calMonth`, `calSel`): Monday-first month grid, each brew day filled with the palettes of the beans brewed (up to 3 side by side), count badge, tap a day for its brews, "Beans tried this month" list. Day squares only animate in when the month first shows (`calAnim`, reset on open/seg/month change); tapping a day just outlines that day. Test photos in `drawdown/tests/labels/`.
- **Grinders:** `GRINDERS` table, 56 models. `kind`: `steps` (numbers/clicks), `ode` (Fellow 1–11 with .1/.2), `rot` (1Zpresso rotation.number.tick), `text` (typed; notation we don't model). `po` = pour-over range from the Honest Coffee Guide chart; V60 zone = finer 57% of it (400–700 of 400–930 µm); start = middle of the V60 zone; `nudge` = clicks for a noticeable change. Functions: `gIdx`, `gStr`, `gZone`, `matchGrinder` (name → model, longest alias wins), `shiftGrind`.
- **AI** (only inside Claude): `sample` capability, resolved once at boot into `AI`. The first AI call shows Claude's consent prompt and **must run synchronously inside a tap** — that's why scanning is photo → preview → "Read label" button. Prompts always include the grinder's notation (`grindNote`).
- **Dial-in engine (no AI):** `extraction()` scores a cup from taste tags, notes words and time vs target; `ruleAdvice(brew, setup, history, bean)` changes one thing: grind ±1–2 nudges, splits the difference when an under- and over-extracted cup of the same beans exist, switches to temperature (±2°) after two grind moves the same way, flags sour+bitter as uneven extraction, keeps good cups (4★+). `starterRecipe(bean, setup)` uses roast level, process, origin, altitude and days off roast on top of the grinder's V60 start. Scenarios are locked in `drawdown/tests/test_app.py`.
- **Grinder renders:** `coffee/assets/grinders/<id>.png` (192 px, transparent), made by `drawdown/render/grinders3d.py` — a numpy SDF raymarcher with five archetypes (hand, box, cone hopper, single-dose, café) and per-model colours/proportions in `LOOK`. Stylised, not product photos. New grinder → add a `LOOK` entry and re-run. Shown via `gImg()` in the setup picker, Gear rows and the Brew screen.
- `APP_VERSION` shows in Settings (small square button top-right of Gear, with a "Check for update" that fetches the live page and compares); bump it on every ship so people can tell if their phone has the new version (GitHub Pages caches ~10 min; home-screen apps longer).
- Sheets: `#sheet-body` is a scrolling flex column, so its children must not shrink (`#sheet-body > *{flex-shrink:0}`, v1.19) — otherwise `.grp` blocks (overflow hidden) get squashed and clipped and nothing scrolls.
- Motion: CSS springs as `linear()` curves (`--spring-soft/bounce/snappy`). Press feedback 97 % / 100 ms ease-out on pointer-down; no bounce on taps; sheets drag-to-dismiss with velocity hand-off and 0.55 rubber band; reduced motion = 200 ms cross-fades.
- Mobile rules applied (Emil Kowalski's `mobile-native` / `apple-design` skills): `viewport-fit=cover`, `interactive-widget=resizes-content`, `touch-action: manipulation`, no text selection on controls, `overscroll-behavior`, safe-area padding, 16 px+ inputs, never disable zoom.

## Brand: drawdown v2 (mono) — current

Inspired by the *feel* of the beean app (black, italic serif titles, square, outlined). Never copy beean's or People Possession's names, logos, colours or layouts. v1 used orange; Jeroen rejected it ("a bit Strava").

- **Name:** drawdown, always lowercase.
- **Mark:** a lowercase d drawn as one pour — kettle stream falls and spirals into the bed. Milk on black, black on milk. Lockup = mark + "drawdown" in Instrument Serif italic. App icon: milk mark on black (`coffee/assets/`).
- **Colour:** black `#000000` ground · `#121212` panels · `#1c1c1c` inside sheets · `#2a2a2a` tracks · `#3a3a3a` hairlines · `#8c8c8c` secondary · `#5e5e5e` inactive · milk `#f4f2ec` text. **No accent.** Only hue: water `#9db8dc` (deep `#2e3a4a`), only for water. Muted taste tones only on cup labels.
- **Type:** Instrument Serif italic for titles (sentence case) · **Allo** for UI (Josh Puckett, OFL, variable 100–900, loaded from jsDelivr `allo-font@1.0.1`; regular/light, never bold; uppercase labels +0.04em) · Geist Mono for brew codes.
- **Shapes:** square everything (0 radius except the app icon). Primary = one solid milk block per screen; secondary = 1.5 px milk outline; icon buttons = outlined squares; rows with full-width hairlines, light-weight values, underlined "Change" links; no tab bar: the two screen titles are the tabs and you swipe between them (v1.23).
- **Brew code:** `15/250 · G4.1 · 94° · 3:00 · ★4` (dose/water · G + grinder notation · °C · time). Brew numbers `BREW 0042`.
- **Cup label:** per brew; taste-colour blocks on top, serif italic bean name, brew code, stars.
- **Voice:** short, specific, a bit cheeky, never snobby. Units always. Verb-first buttons. No exclamation marks, no emoji.
